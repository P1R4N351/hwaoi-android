# Koei Tecmo KTGL Commonalities & Cross-Venture Optimizations (`AoC` + `AoI`)

Both **[AoC Native](https://github.com/P1R4N351/hwaoc-android)** (*Hyrule Warriors: Age of Calamity*, `01002B00111A2000`, update `v327680` / `1.3.0`) and **[AoI Native](../README.md)** (*Hyrule Warriors: Age of Imprisonment*, `04003F40232DE000`, update `v196608`) are built by Koei Tecmo (Omega Force) on successive generations of the same **KTGL** + **KIDS** engine stack. Insights and fixes uncovered on either title carry directly across both ports.

---

## 2. Cross-Venture Optimizations Implemented

### Optimization 1 — AoI (`DM_VK_EDGE_UNPIN=1`): Shared Boundary Page Unpinning & Edge Polling

- **Root Cause (Observed Live on AYN Thor):** KTGL sub-allocates small textures onto shared `4 KiB` pages adjacent to active CPU writes. Each re-protection triggers a `SIGSEGV`, and `nvn_dirty.c` `fault_run()` (`g_frun = 256`) releases up to `257` contiguous `PG_PROT` pages per shared page (`2 * 257 = 514` faults/frame), forcing a full scan of all `757` live images on every submission.
- **Implementation:**
  - [`dm/gfx/vk_android/vka_edge_unpin.h`](../dm/gfx/vk_android/vka_edge_unpin.h), [`dm/gfx/vk_android/vka_tex.c`](../dm/gfx/vk_android/vka_tex.c), [`dm/gfx/vk_android/vka.h`](../dm/gfx/vk_android/vka.h), and [`dm/gfx/tests/t_edge_unpin.c`](../dm/gfx/tests/t_edge_unpin.c).
  - Splits each tracked texture address span into partial boundary ranges `r[0]`, `r[1]` and exclusive interior pages `[ia, ie)`.
  - After `VKA_EDGE_UNPIN_AFTER` (`2`) consecutive neighbor-only skips, registers the texture in compact side-list `g_edge_hot[256]`, leaves shared boundary pages writable, keeps `[ia, ie)` write-protected via `PG_PROT`, and polls `[r0]`/`[r1]` via 64-bit hash comparison on every submit — skipping `SIGSEGV`, `mprotect`, and `full_scan`.
  - During the 2-frame warmup on straddling multi-page textures, snapshots an interior hash (`<= 1 MiB`) so `fault_run` collateral page releases are distinguished from genuine interior writes.

### Optimization 2A — AoC (`!vk_off("edgeguard")`): Pool-Aligned `64 KiB` Edge Hash Guard & Unpinning

- **Gap Addressed in AoC:** On Android/Linux, `nvn_dirty.c` protects memory in **`64 KiB` (`16`-page) units** (`g_unit`), and [`vk_res.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_res.c) lacked sub-range edge hashing. Any small static KTGL texture sharing a `64 KiB` unit with per-frame CPU writes suffered both a fault storm and a **full Vulkan texture deswizzle + staging copy + 2 `vk_barrier_all` barriers** on every submission.
- **Implementation:**
  - [`nvn_dirty_unit_info`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/third_party/d2r_gfx/gfx/nvn/nvn_dirty.c) + [`vk_edge_guard.h`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_edge_guard.h) + `vk_res.c` + `test_vk_ktgl_opt.c`.
  - `nvn_dirty_unit_info()` exposes the exact pool-aligned `64 KiB` unit base so boundary splitting aligns with `mprotect` granularity.
  - Snapshots head/tail sub-unit edge hashes (plus warmup interior collateral hash), unpins shared boundary units after `VK_EDGE_UNPIN_AFTER` (`2`) neighbor-only skips, and protects only exclusive full interior `[ia, ie)` units.

### Optimization 2B — AoC (`!vk_off("quadbatch")`): Pre-Pass Indirect `QUADS` Compute Batching

- **Gap Ported from AoI:** Converting GPU-pending indirect `QUADS` draws inline inside `draw_indirect` calls `vk_end_rendering_at(VK_PASS_END_COMPUTE, 0)` on each draw, splitting Adreno TBDR render passes per indirect quad draw.
- **Implementation (ported from AoI [`vka_exec.c`](../dm/gfx/vk_android/vka_exec.c) / [`vka_draw.c`](../dm/gfx/vk_android/vka_draw.c)):**
  - [`vk_quad_batch.h`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_quad_batch.h) + [`vk_draw.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_draw.c) + [`nvn_vk.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/nvn_vk.c).
  - `vk_qi_scan_ops()` walks upcoming opcodes (`OP_CALL` depth `16`, bounded at `64` items / `4,096` ops) before `begin_rendering_inner` opens the render pass (and on cache misses in `draw_indirect`), stopping cleanly on any buffer-write hazard (`OP_COPY_B2B`, `OP_UPDATE_UB`, `OP_DISPATCH`, `OP_SIGNAL_EVENT`, `OP_REPORT_COUNTER`, non-primitive `OP_BARRIER`) or target change (`OP_SET_RT`).
  - `quad_indirect_convert_batch()` converts up to `64` unique indirect `QUADS` buffers in one compute dispatch pass with a single `vkUpdateDescriptorSets` call and caches results keyed by `(submit_serial, vk_gpu_write_gen)`.


### Optimization 3 — AoI (`DM_MOVIE_LOOP_OPT=1`, `DM_MOVIE_FAST_NV12=1`) + AoC (`TOTK_MOVIE_MT=1`, `TOTK_MOVIE_FAST_NV12=1`): VP9 Row-MT / Loop-Filter Multithreading & Border-Only NV12 Packing

- **Root Cause Across Both Titles:**
  - **AoC (`movie_host.c`)** configured `libvpx` VP9 decoders with `threads = 4` in both `h_configure` and `h_flush` without enabling `VP9D_SET_ROW_MT` or `VP9D_SET_LOOP_FILTER_OPT`, leaving worker threads underutilized on 1–2 tile KTGL `.webm` cutscenes. It also copied Y planes row-by-row even when `stride == width`.
  - **AoI (`hle_movie.c`)** enabled `VP9D_SET_ROW_MT` without `VP9D_SET_LOOP_FILTER_OPT`, copied tight `stride == width` Y planes row-by-row, and pre-`memset` the entire `w * h * 1.5` (`3.1 MiB` at `1080p`) output buffer whenever `cw < w || ch < h` before overwriting the active rectangle.
- **Implementation:**
  - **AoI:** [`dm/host/hle_movie_nv12.h`](../dm/host/hle_movie_nv12.h), [`dm/host/hle_movie.c`](../dm/host/hle_movie.c), [`dm/host/tests/t_movie_vpx.c`](../dm/host/tests/t_movie_vpx.c) — adds `VP9D_SET_LOOP_FILTER_OPT=1` (`DM_MOVIE_LOOP_OPT=1`), single contiguous Y `memcpy` when `cw == w && y_stride == w`, and border-only right/bottom `16`/`128` padding (`DM_MOVIE_FAST_NV12=1`).
  - **AoC:** [`movie_host.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/runtime/movie_host.c) + [`movie_nv12.h`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/runtime/movie_nv12.h) — calls `configure_vp9_mt()` (`VP9D_SET_ROW_MT=1` + `VP9D_SET_LOOP_FILTER_OPT=1`) in both `h_configure` and `h_flush` (`TOTK_MOVIE_MT=1`), plus `totk_movie_to_nv12()` contiguous Y copy & NEON `vst2q_u8` (`TOTK_MOVIE_FAST_NV12=1`).
- **Observed Nuances (Scientific Check):** On Apple Silicon arm64 (`libvpx` `1080p`, `4` threads), `ROW_MT + LOOP_FILTER_OPT` yields **`1.27x–1.28x`** on 1–2 tile streams over AoC's prior `row0/opt0` baseline (`7.666 -> 6.028 ms` on 1 tile, `4.429 -> 3.467 ms` on 2 tiles), while `LOOP_FILTER_OPT` alone adds `~1.03x–1.04x` over `ROW_MT` and is flat (`2.746 -> 2.749 ms`) when 4 tiles already saturate 4 threads. For `md_nv12`, eliminating the `3.1 MiB` full-frame `memset` yields **`1.25x–1.38x`** on `720p -> 1080p` border-padded frames, whereas already-contiguous `1080p` is DRAM-bandwidth-bound (`1.02x–1.04x`).

### Optimization 4 — AoI (`DM_VK_KTGL_CACHE=1`) + AoC (`!vk_off("ktglmemo")`): Zero-Write `512x4` Separable Program & Layout Front-Caches + Narrow `QUADS` Barriers

- **Root Cause Across Both Titles:** KTGL binds separable per-stage `NVNprogram` objects (`VS`, `FS`, `CS`) across `350–1,000+` draws/frame. Direct-mapped `64`-slot program caches (`g_pm[64]` in AoI `vka_draw.c`, `g_progc[64]` modulo-`64` in AoC `vk_shader.c`) and `1`-entry layout memos (`lsh` in AoI, `last_layout` in AoC `vk_draw.c`) thrashed on alternating KTGL shaders, taking `pthread_mutex_lock` + FNV/`nvn_hm_get` slow paths against background PSO workers. In addition, indirect `QUADS` conversion emitted `3` global `ALL_COMMANDS` barriers per batch.
- **Implementation:**
  - **AoI:** [`dm/gfx/vk_android/vka_ktgl_cache.h`](../dm/gfx/vk_android/vka_ktgl_cache.h), [`dm/gfx/vk_android/vka_draw.c`](../dm/gfx/vk_android/vka_draw.c), [`dm/gfx/vk_android/vka_exec.c`](../dm/gfx/vk_android/vka_exec.c), [`dm/gfx/tests/t_ktgl_cache.c`](../dm/gfx/tests/t_ktgl_cache.c) — zero-write `4`-way set-associative `512x4` (`2,048`-entry) program cache (`vka_ktgl_pm_cache`, preserving `VKA_BAD_MISSING` `vka_layer_gen()` invalidation), `512x4` (`2,048`-entry) SplitMix64 graphics layout cache (`vka_ktgl_lay_cache`), `32x4` (`128`-entry) compute layout cache (`vka_ktgl_cs_cache`), plus narrow `TRANSFER -> COMPUTE_SHADER` and `COMPUTE_SHADER -> DRAW_INDIRECT` barriers in `qdx_convert()`.
  - **AoC:** [`vk_ktgl_memo.h`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_ktgl_memo.h), [`vk_shader.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_shader.c), [`vk_draw.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_draw.c) — zero-write `512x4` (`2,048`-entry) `vk_progc_memo` (with non-mutating `vk_progc_peek` for `vk_prog_predict`), `512x4` (`2,048`-entry) SplitMix64 `vk_lay_memo`, widened `pipe_get` `memo[256]`, narrow `VkMemoryBarrier2` barriers in `quad_indirect_convert_batch` & `quad_indirect_convert`, and fixed pre-existing `GAME_HWAOC` guard assertion in `tests/test_companion_state.py`.

### Optimization 5 — AoI (`DM_VK_PSO_MEMO=1`, `DM_FS_FAST_IMG=1`) + AoC (`!vk_off("ktglmemo")`, `TOTK_ROMFS_FAST=1`): Multi-Way PSO Front-Memos & Lock-Free Read-Side RomFS/NUP Paths

- **Root Cause Across Both Titles:**
  - **Graphics/Compute PSO lookup lock contention:** Even after caching separable programs and pipeline layouts (Opt 4), KTGL draws/dispatches still took a global PSO table mutex (`g_mu` in AoI `vka_pso.c`, `mu` + `nvn_hm_get` in AoC `vk_draw.c` / `vk_compute.c`) to look up compiled `VkPipeline` handles (`64`-slot direct-mapped cache in AoC thrashed across ~320 pipelines; AoI had no lock-free PSO front-cache and `cs_obtain` missed release barriers on async hit publication).
  - **Read-side VFS lock contention:** Both titles issue frequent read/stat calls against static compressed/packed archives (`NUP` zstd + RomFS mounts in AoI; `runtime_romfs_read`/`size` + `65,536`-slot handle table in AoC) while holding a coarse global lock on every lookup/read.
- **Implementation:**
  - **AoI:** [`dm/gfx/vk_android/vka_pso_cache.h`](../dm/gfx/vk_android/vka_pso_cache.h), [`dm/gfx/vk_android/vka_pso.c`](../dm/gfx/vk_android/vka_pso.c), [`dm/gfx/tests/t_pso_cache.c`](../dm/gfx/tests/t_pso_cache.c), [`dm/host/nup_image.h`](../dm/host/nup_image.h), [`dm/host/hle_fs.c`](../dm/host/hle_fs.c), [`dm/host/tests/t_nup_fast.c`](../dm/host/tests/t_nup_fast.c) — adds zero-RSS static `.bss` `512x4` dynamic-VIN (`<= 320` B) + `64x4` static-VIN (`<= 1,152` B) + `128x4` CS zero-write PSO front-caches (`DM_VK_PSO_MEMO=1`, preserving GPL `linked -> optimized` upgrades), release-published async `cs_obtain` hits, O(1) intrusive doubly-linked LRU eviction in `nup_z_trim`, lock-free CAS `nup_z_pin_read`/`nup_z_unpin_read` when `OpenFile` holds `refs >= 1`, and lock-free `img_path_fast` (`DM_FS_FAST_IMG=1`) for read-only non-overlay image mounts.
  - **AoC:** [`vk_ktgl_memo.h`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_ktgl_memo.h), [`vk_draw.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_draw.c), [`vk_compute.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/android/gfx/vk_compute.c), [`romfs_handles.h`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/runtime/romfs_handles.h), [`romfs.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/runtime/romfs.c) — upgrades `vk_pipe_memo` to O(1) SplitMix64 `1024x4` (`4,096` slots), adds `64x4` `vk_cs_memo` with release-published `e->state` and single-lock cold `vk_compute_pipeline`, and adds C11 seqlock handle resolution + O(1) FIFO `free_ring` (`TOTK_ROMFS_FAST=1`) with zero `GAME_*` branches.

### Optimization 6 — AoI (`DM_AUDIO_FAST=1`) + AoC (`TOTK_AUDIO_FAST=1`): KTSL2 Audio Mixing, Single-Pass ADPCM Resampling & Callback Ring Fast Paths

- **Root Cause Across Both Titles:**
  - **AoC (`audio_mixer.c`)** decoded each active mono/stereo `FMT_PCM16` voice via per-sample `Walk` struct copies + `walk_step()`/`sample_at()`, decoded `FMT_ADPCM` twice per sample (`s0` and `s1` lookahead), processed started zero-volume voices and zero-gain submixes through full channel-mix loops (`accumulate()`), ran `6 -> 2` sink downmix with per-sample channel-presence branches inside `frames`, and copied ring buffers sample-by-sample with `% RING_FRAMES` in `output_push()` / `pull_frames()`.
  - **AoI (`hle_audren.c`, `hle_audio.c`)** materialized an intermediate `int32_t st[FRAME_MAX * 2]` downmix buffer at `48 kHz` before clamping and computing `loud`/`peak`, and ran scalar loops for `6 -> 2` `int16_t` `AudioOut` downmix (`pull_device_x`) and PCM16 `SetAudioOutVolume` scaling (`pull_x`).
- **Implementation:**
  - **AoI:** [`dm/host/hle_audio_fast.h`](../dm/host/hle_audio_fast.h), [`dm/host/hle_audren.c`](../dm/host/hle_audren.c), [`dm/host/hle_audio.c`](../dm/host/hle_audio.c), [`dm/host/tests/t_audio_fast.c`](../dm/host/tests/t_audio_fast.c) (`DM_AUDIO_FAST=1`) — fuses `48 kHz` `6->2` Q15 downmix + clamp + `loud` + `peak` reduction in `int64x2_t` NEON (`vmull_n_s32`/`vshrn_n_s64`, computing `vabsq_s32` peak before `int16_t` narrowing so `-32768` yields `+32768`), vectorizes `32 kHz` clamp+peak (`dm_audren_clamp_peak`), vectorizes `AudioOut` `6->2` `int16_t` Q15 downmix in `int64_t` (avoiding `int32_t` overflow on all-`-32768` inputs), and vectorizes PCM16 float volume scaling (`vcvtq_s32_f32`).
  - **AoC:** [`audio_fast.h`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/runtime/audio_fast.h), [`audio_mixer.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/runtime/audio_mixer.c), [`test_audio_fast.c`](https://github.com/P1R4N351/hwaoc-android/blob/main/games/totk/runtime/test_audio_fast.c) (`TOTK_AUDIO_FAST=1`, `0` `GAME_*` branches) — uses 1–2 contiguous `memcpy` spans across `RING_FRAMES` wrap + IEEE-exact `0x7fffffff` `-0.0f`-safe NEON nonzero stereo scan, prunes non-ADPCM/non-biquad silent voices & zero-gain submixes cleanly, adds NEON/unit-step `FMT_PCM16` + single-pass `FMT_ADPCM` decoding (restoring `v->adpcm` before the final `+1` interpolation lookahead), NEON `vfmaq_n_f32` mix accumulation, and hoisted `6 -> 2` / `2 -> 2` sink downmix.

### Optimization 7 — AoI (`DM_VK_LC_FAST=1`, `DM_OPUS_FAST=1`) + AoC (`!vk_off("ktglmemo")`, `TOTK_OPUS_FAST=1`): Set-Associative GPU VA / Interval-Exact Lag Caches, Compute Driver-UBO Memoization & Lock-Free Hardware Opus Fast Paths

- **Root Cause Across Both Titles:**
  - **GPU VA -> VkMemory/Buffer & Lag Bound Lookups:** Even after 1-entry MRU front caches, high-churn texture/buffer draws and `vk_lag_bound` sweeps spilled to binary search + `pthread_rwlock_rdlock` (`vka_mem.c` `lookup()` in AoI; `nvn_vk.c` `span_best_fast()` over `64` hints, `resolve_local()`, `record_resolve_inner()`, and full linear scan under `lag_va_lock` in AoC). In addition, AoI `vka_draw.c` skipped compute driver-UBO memoization (`g_dm[5]`) completely.
  - **Hardware Opus Decoding & Frame Peak Scans:** AoC `opus_codec.c` serialized every `512`-slot hardware Opus decode under a single global `mu` mutex (`g_decoders` linear walk + `opus_decoder_ctl(OPUS_GET_NB_CHANNELS)`). AoI `hle_codec.c` resolved `objmap` handles under a global mutex (`GetOpusDecoderChannelCount` / `g_mdec_lock` list walk), freed request structs via heap `free`/`malloc` churn, and ran a scalar PCM16 peak scan (`-32768 -> +32768`).
